# FOLLOW visual system — light refresh

The user's latest direction replaces the original dark interface: make the app brighter, attractive, legible and easy to understand. This takes precedence over earlier dark screenshots and palette descriptions.

Use a pale lavender-white workspace, white surfaces, ink typography and violet actions. Restrained green process tints, blue figure tints and warm metric tints communicate visual type. Status is always paired with text. Sora and Inter remain self-hosted. All color and elevation definitions live in src/styles/tokens.css.

Entry starts with the real curated demo, a clear three-step explanation and an interactive shared-canvas preview. Import remains available. PDF reading is local, uses the pulled browser extraction module, and reports actual page progress. A byte/hash/page/quote match opens the curated source; arbitrary PDFs are not falsely presented as generated projects.

Studio is an Operate surface: 68 px header, 252 px concept rail, 304 px selected inspector and a framed central workspace. Topic cards, relationship lines, selected sidebar rows, current-topic breadcrumbs and contextual guidance make state changes visible. The Reveal next point strip exposes the frequent action. Supporting points precede a collapsible content editor. Advanced diagnostics sit behind Tools.

Audience is an Experience surface: a light 16:9 stage, 5% horizontal and 6% vertical safe margins, source-backed material and minimal chrome. No presenter transcript, notes or editing controls appear. Fullscreen still requires a user gesture.

Focused process compositions have an 800-unit height budget to fit the actual demo labels. Comparisons show approved revealed points in place of a redundant summary; no points or source facts are silently shortened. Stable home positions and previous reveals are preserved. Keyboard and manual framing remain immediate; automatic movement and reduced-motion behavior keep the existing contract.

On mobile, project inspection and the text outline remain available, and the interface explicitly recommends desktop for presenting. The canvas toolbar fits its viewport without exposing unnecessary layout controls.
